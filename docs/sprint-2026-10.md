## How the sprint runs

- **Orchestrator** (Opus, the planning session) dispatches lanes as `Agent` subagents, gates,
  merges and writes one report. It takes back conclusions only.
- **One lane = one worktree** at `~/dev/wt-partiskatt-<lane>` on branch `sprint/<lane>` from main
  (WORKSPACE.md). Never inside the repo.
- **Lane gate**, run by the lane: `npm ci`, then `npm run check` on the untouched tree (baseline
  must be green), then the change, then `npm run check` again plus the lane's acceptance and at
  least one anti-vacuity mutation whose red output the lane reports.
- **e2e is run by the orchestrator only**, one worktree at a time, because `playwright.config.ts`
  pins port 4912 with `reuseExistingServer` and parallel lanes would test each other's server.
  Lanes that serve the app for manual checks use `--port 49<lane nr>`.
- **Number-bearing lanes (★)** get a Codex second opinion via `~/.claude/bin/delegate` that
  recomputes the new numbers from their sources before merge. A disagreement blocks the merge.
- **Merge**: the orchestrator rebases onto main, regenerates `DATA_STATUS.md` with the repo's
  script, reruns `npm run check`, runs e2e, fast-forwards, pushes, and removes the worktree and
  branch in the same step. CI on origin must stay green.
- **Shared prose**: METHODOLOGY.md and `src/views/MethodView.tsx` are edited by five lanes. Each
  lane edits only its own section heading; the orchestrator resolves text conflicts at rebase.
- **Sources**: `scripts/fetch-sources.sh` does not exist (never committed). Archive by hand: the
  raw file in `sources/raw/`, a text extraction in `sources/text/` for legal text, a manifest row
  with sha256 and byte count (`src/tests/manifest-integrity.test.ts`). L3 and L7 both append to
  `sources/manifest.json` and merge one after the other.
- **Never**: push or merge from a lane, touch main from a lane, new QUEUE.md entries, marking
  anything `confirmed`, a number without a source or an explicit `ANSLAG`, reading PDFs in the
  orchestrator thread.

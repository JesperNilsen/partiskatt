## How the sprint runs

- **Fresh session** from `~/Claude programmer/partiskatt`. This file is the plan;
  the orchestrator copies it to `docs/sprint-2026-09.md` in its first commit.
- **Orchestrator** (Opus) dispatches lanes as `Agent` subagents, merges, and
  writes the report. It takes back conclusions only. It runs `/context-save` at
  each batch boundary, since it will cross the 200k cap mid-sprint.
- **One lane = one worktree** at `~/dev/partiskatt-<lane>` on branch
  `sprint/<lane>` from main (WORKSPACE.md). Never inside the repo.
- **Lane gate**, run by the lane: `npm ci && npm run check` (typecheck, vitest,
  `reconcile --check`, `data-status --check`, build) plus the lane's own
  acceptance and anti-vacuity lines. A lane reports the observed red output of
  every anti-vacuity mutation.
- **Independent check for number-bearing lanes** (marked ★): before merge, the
  orchestrator sends the lane diff to Codex via `~/.claude/bin/delegate` for a
  capped second opinion that recomputes every new number from its source. L10a is
  the exception: Codex cannot read image pages, so its check is a second,
  independent vision read. A disagreement blocks the merge until resolved.
- **Merge**: orchestrator rebases the lane onto main, reruns `npm run check`,
  fast-forwards, pushes, and removes worktree + branch in the same step. CI on
  origin must stay green.
- **Queue bookkeeping (step 0, one commit)**: the stranded `running:` line on
  Q-010 and every entry the sprint absorbs become `blocked:sprint 2026-09-25`,
  so the scheduled queue-runner cannot pick them up mid-sprint. Each flips to
  `done` with a `result:` line when its lane merges; Q-001 flips to `done` with
  Q-010. No new queue entries.
- **Never**: new QUEUE.md entries, reading PDFs or `sources/text/*` in the
  orchestrator thread, marking anything `confirmed` (gate 3 is Jesper's),
  inventing a number without a source or an explicit `ANSLAG`.

**Decisions taken 2026-09-25 (Jesper):**
(1) mid-year rules stay **full-year policy rates**, documented as full-year effect;
(2) relative party proposals are **derived where the arithmetic is unambiguous**,
against the Prop. 1 LS baseline the party wrote against, marked `estimated` with a
derivation note; the rest stay unquantified with the reason;
(3) **MIT for code, CC BY 4.0 for method text and encoded numbers.** Going
public and the Netlify link stay Jesper's switches.

- **Ports**: Vite uses strict ports (4893 / 4722). Any lane that serves the app
  passes its own port (`--port 49<lane nr>`), never the defaults.
- **Generated files**: every rebase regenerates `DATA_STATUS.md`,
  `RECONCILIATION.md` and the `*.reconciled.md` sheets with the repo's own
  scripts before `npm run check`. Never hand-edit them.
- **Dispatch on dependencies, not batches**: up to 4 lanes at once; a lane starts
  when the lanes it depends on have merged.
